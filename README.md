# WallFlow 4K

แอพวอลเปเปอร์ส่วนตัวสำหรับ Android 10 ขึ้นไป ทดสอบเป้าหมายหลักที่ Samsung Galaxy S25+ (One UI / Android 16)

เพิ่มรูปและวิดีโอได้ **ไม่จำกัดจำนวน** ทั้งหน้าจอหลักและจอล็อก โดยไม่แตะโควตา 15 รูปของ One UI และไม่คัดลอกไฟล์ต้นฉบับ

---

## ปัญหาที่แอพนี้แก้

| ข้อจำกัดเดิมของ One UI | วิธีที่ WallFlow ใช้แก้ |
|---|---|
| จอล็อกใส่ได้ 15 รูป/วิดีโอ | ไม่ใช้ระบบ wallpaper ของ Samsung เลย แอพเรียก `WallpaperManager.setBitmap()` เองทีละรูป ระบบไม่ได้จำกัดจำนวนครั้ง จึงวนรูปได้ไม่สิ้นสุด |
| หน้าจอหลักใส่ภาพนิ่งได้ 1 รูป | ติดตั้ง Live Wallpaper ของแอพไว้ช่องเดียว แล้วแอพสลับเนื้อหาข้างหลังเอง ตั้งครั้งเดียวจบ ไม่ต้องกลับไปที่ตัวตั้งค่าวอลเปเปอร์อีก |
| Live Wallpaper ทั่วไปทำให้นาฬิกาจอล็อกไม่เปลี่ยนสี | engine ของเรา override `onComputeColors()` ส่ง `WallpaperColors` ให้ระบบทุกครั้งที่เปลี่ยนภาพ นาฬิกาจึงปรับสีตามรูปเหมือนภาพนิ่งปกติ |
| แอพวอลเปเปอร์ส่วนใหญ่คัดลอกไฟล์ กินพื้นที่ซ้ำ | เก็บแค่ URI แบบถาวร (SAF persistable grant) ไฟล์ 4K ยังอยู่ที่เดิม แอพกินพื้นที่หลักสิบ KB บวกแคชรูปย่อที่จำกัดไว้ 48 MB |

## ฟีเจอร์

- **รูปและวิดีโอไม่จำกัด** แยกคิวหน้าจอหลัก / จอล็อก หรือซิงก์ให้เหมือนกันก็ได้
- **ตั้งพร้อมกันในครั้งเดียว** โหมดซิงก์ใช้ `FLAG_SYSTEM or FLAG_LOCK` ในคำสั่งเดียว ทั้งสองจอเปลี่ยนพร้อมกันเป๊ะ
- **เชื่อมโฟลเดอร์** ชี้ไปที่เช่น `DCIM/Wallpapers` ครั้งเดียว ไฟล์ที่ใส่เพิ่มทีหลังเข้าคลังเองเมื่อกดสแกน
- **เปลี่ยนรูปได้ 4 แบบ** ปิด / ทุกครั้งที่ปลดล็อก / ตามเวลา 1 นาที–12 ชั่วโมง / แตะสองครั้งบนหน้าจอหลัก
- **รองรับ 4K** ถอดรหัสแบบ sampled ตามขนาดจอจริง ไม่โหลดภาพ 4K ทั้งใบเข้าแรม
- **ประหยัดแบต** วิดีโอหยุดเองเมื่อปิดหน้าจอหรือเปิดแอพอื่นเต็มจอ ตั้งให้หยุดเมื่อแบตต่ำกว่า N% ได้
- **นาฬิกาวงกลมบนวอลเปเปอร์** วันที่ สภาพอากาศ และนัดถัดไป วาดทับรูปโดยตรงจึงขึ้นทั้งสองจอ
- **ออฟไลน์เป็นค่าเริ่มต้น** ออกเน็ตเฉพาะตอนเปิดสภาพอากาศ ซึ่งส่งแค่พิกัดที่ปัดแล้วไป Open-Meteo

## สิทธิ์ที่ขอ

ทั้งหมดเป็น normal permission ที่ได้ตั้งแต่ติดตั้ง ไม่มีป๊อปอัปถาม (ตรวจจาก APK จริงด้วย `aapt2 dump permissions`)

- `SET_WALLPAPER` เปลี่ยนวอลเปเปอร์
- `RECEIVE_BOOT_COMPLETED` ตั้งนาฬิกาปลุกใหม่หลังรีบูต
- `ACCESS_NETWORK_STATE` ติดมากับไลบรารี Media3 (ExoPlayer) โค้ดของเราไม่ได้เรียกใช้
- `INTERNET` ใช้เฉพาะคำขอสภาพอากาศ
- `ACCESS_COARSE_LOCATION` ใช้เฉพาะคำขอสภาพอากาศ ขอตอนผู้ใช้เปิดสวิตช์ ไม่เคยขอตำแหน่งแม่นยำ
- `READ_CALENDAR` ใช้เฉพาะวาดตารางกิจกรรม อ่านแล้วทิ้ง ไม่เก็บไม่ส่ง

ตั้งใจ **ไม่ขอ** `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, `ACCESS_FINE_LOCATION` และ foreground service เพราะเข้าถึงสื่อผ่าน SAF ซึ่งแคบกว่าและปลอดภัยกว่า สองสิทธิ์สุดท้ายขอตอนรันไทม์ และถ้าไม่อนุญาต overlay จะซ่อนส่วนนั้นไปเฉยๆ

## โครงสร้างโปรเจกต์

```
app/src/main/java/com/admrichest/wallflow/
├─ WallFlowApp.kt                 Application + ตั้งเพดานแคชรูปย่อ
├─ data/
│  ├─ MediaItem.kt                รายการหนึ่งชิ้นในคลัง
│  ├─ LibraryRepository.kt        เก็บ/อ่าน library.json, จัดการ persistable URI
│  └─ Settings.kt                 ค่าตั้งทั้งหมด (SharedPreferences)
├─ wallpaper/
│  ├─ GlPainter.kt                วาดภาพนิ่งและวิดีโอด้วย OpenGL บน surface เดียวกัน
│  ├─ ImageUtils.kt               ถอดรหัสแบบ sampled, center-crop, ดึงเฟรมวิดีโอ
│  ├─ WallpaperApplier.kt         เขียนภาพนิ่งลง FLAG_SYSTEM / FLAG_LOCK
│  ├─ PlaybackController.kt       ตัวกลางตัดสินว่า "ตอนนี้ควรโชว์อะไร"
│  ├─ RotationScheduler.kt        AlarmManager สำหรับโหมดตามเวลา
│  ├─ RotationReceiver.kt         รับปลุก + ตั้งใหม่หลังรีบูต
│  └─ WallFlowWallpaperService.kt Live Wallpaper engine (ExoPlayer + Canvas + WallpaperColors)
└─ ui/                            Jetpack Compose
```

## ⚠️ คีย์เซ็นชื่อถูกสร้างแล้ว — สำรองด่วน

`keystore/release.jks` กับรหัสผ่านใน `keystore.properties` ถูกสร้างไว้แล้วในโปรเจกต์นี้

คีย์นี้คือสิ่งที่ผูกแอพกับตัวคุณ **ถ้าหายแล้วยังไม่ได้อัปโหลดขึ้น Play คุณจะอัปเดตแอพที่ติดตั้งไว้ไม่ได้ ต้องถอนแล้วติดตั้งใหม่** คัดลอกโฟลเดอร์ `keystore/` ทั้งโฟลเดอร์ไปเก็บใน Google Drive หรือ password manager ตั้งแต่ตอนนี้

(ถ้าอัปโหลดขึ้น Play แล้วเปิด Play App Signing ไว้ คีย์นี้จะกลายเป็นแค่ upload key ซึ่งขอรีเซ็ตกับ Google ได้ ปลอดภัยขึ้นมาก)

## สถานะโปรเจกต์

build ผ่านแล้วบนเครื่องนี้ด้วย AGP 8.11.1 / Gradle 8.14.2 / Kotlin 2.1.21 / compileSdk 36

| ไฟล์ | ขนาด |
|---|---|
| `app-release.aab` (สำหรับ Play) | 4.4 MB |
| `app-release-unsigned.apk` | 3.7 MB |
| `app-debug.apk` | 60 MB (ไม่ย่อโค้ด ใช้ทดสอบเท่านั้น) |

**ยังไม่ได้ทดสอบรันบนเครื่องจริง** โค้ดคอมไพล์และแพ็กผ่านครบ แต่พฤติกรรมบนหน้าจอ เช่น การสลับวิดีโอ การมิเรอร์จอล็อก และการปรับสีนาฬิกา ต้องยืนยันบน S25+ จริงอีกครั้ง ดูวิธีติดตั้งทดสอบใน [docs/01-build-และติดตั้ง.md](docs/01-build-และติดตั้ง.md)

### ประวัติการแก้

**1.3.0** — นาฬิกาวงกลมบนวอลเปเปอร์

วาดเป็นเลเยอร์ใน GL pipeline เดิม (`OverlayRenderer.kt`) ไม่ใช่ Always On Display ซึ่งแอพภายนอกเข้าไม่ถึง และไม่ใช่ Activity ค้างจอซึ่งกินแบต เพราะวาดทับวอลเปเปอร์โดยตรง จึงขึ้นทั้งหน้าจอหลักและจอล็อก และหยุดเองพร้อม engine ตอนปิดจอ

- วงแหวนบางเดินตามนาทีของชั่วโมง เวลาอยู่กลางวง วันที่อยู่ใต้วง ขาวล้วนพร้อมเงานุ่มเพื่อให้อ่านออกทั้งบนรูปสว่างและรูปมืด
- สภาพอากาศจาก Open-Meteo ไม่ต้องมี API key ปัดพิกัดเหลือทศนิยม 2 ตำแหน่งก่อนส่ง แคช 30 นาที ใช้เฉพาะตำแหน่งล่าสุดที่ระบบมีอยู่แล้ว ไม่ปลุก GPS
- ตารางกิจกรรมสูงสุด 3 รายการ อ่านจากปฏิทินแล้ววาดแล้วทิ้ง ไม่เก็บไม่ส่ง
- วาดใหม่นาทีละครั้งเฉพาะตอนจอเปิด
- แต่ละส่วนปิดตัวเองเงียบๆ ถ้าไม่ได้รับสิทธิ์

**เพิ่ม 3 สิทธิ์** `INTERNET`, `ACCESS_COARSE_LOCATION`, `READ_CALENDAR` และ **แบบฟอร์ม Data safety เปลี่ยนไปแล้ว** ดูคำตอบที่ถูกต้องใน [docs/02](docs/02-อัปโหลด-google-play.md) หัวข้อ 5.6

**1.2.0** — วิดีโอเล่นบนจอล็อกแล้ว ยืนยันบนเครื่องจริง (`isPlaying=true role=LOCK` + 4 เฟรมต่างกันขณะ `mDreamingLockscreen=true`)

- **แยกบทบาท engine ด้วย `wallpaperFlags`** (API 34+) วอลเปเปอร์ที่คุมสองจอได้ Engine คนละตัวต่อจอ เดิมทั้งคู่ทำตัวเหมือนกัน engine จอล็อกจึงเลื่อนคิวทุกครั้งที่จอล็อกโผล่ ผลคือจอล็อกแสดงรูปถัดไปเสมอ ไม่ใช่รูปที่ควรแสดง ตอนนี้มีแต่ engine จอหลักที่เลื่อนคิว เพราะจอล็อกโผล่คือการวางเครื่อง ไม่ใช่การปลดล็อก
- **engine จอล็อกอ่านคิวจอล็อกของตัวเอง** โหมดแยกสองจอจึงใช้ได้จริงกับ live wallpaper เป็นครั้งแรก
- **ปิดมิเรอร์เป็นค่าเริ่มต้น พร้อม migration ล้างค่าเดิม** ของเดิมเปิดไว้และเป็นตัวทำลายจอล็อกเอง

**1.1.3 / 1.1.4** — แก้ตัวกันการมิเรอร์ที่ใช้ไม่ได้จริง

`getWallpaperInfo(FLAG_LOCK)` คืนค่า null บนเครื่องที่ใช้ engine ร่วมสองจอ เพราะไม่มีวอลเปเปอร์จอล็อกแยกให้บรรยาย ตัวกันใน 1.1.1 จึงอ่านว่า "ไม่มี live wallpaper บนจอล็อก" แล้วเขียนภาพนิ่งทับวิดีโอของตัวเอง ตอนนี้เพิ่มเงื่อนไข: จอล็อกที่ไม่มีวอลเปเปอร์ของตัวเอง = กำลังใช้ของหน้าจอหลัก = ห้ามมิเรอร์

**1.1.1** — ทดสอบบนเครื่องจริงผ่าน adb แล้ว ทุกข้อด้านล่างยืนยันด้วย log และสกรีนช็อต

- **วาดทุกอย่างผ่าน OpenGL แทน Canvas** (`GlPainter.kt`) นี่คือตัวแก้จริงของอาการวิดีโอไม่เล่น Surface ที่ถูก `lockCanvas()` จะผูกกับ CPU buffer API และ MediaCodec เชื่อมต่อไม่ได้อีก พอแอพวาดภาพนิ่งก่อน วิดีโอจึงไม่มีที่ลง ทั้ง `setFormat()` และ `setFixedSize()` ขอ surface ใหม่ไม่ได้ (ระบบตอบ "Wallpapers currently only support sizing from layout") จึงต้องเลิกใช้ Canvas ทั้งหมด ตอนนี้ภาพนิ่งเป็น texture 2D วิดีโอเป็น external OES texture ผ่าน SurfaceTexture ใช้ GL context เดียวกัน
- **ไม่มิเรอร์ภาพนิ่งทับจอล็อกเมื่อ engine อยู่บนจอล็อกอยู่แล้ว** ตรวจด้วย `getWallpaperInfo(FLAG_LOCK)` เดิมจะเอาภาพนิ่งไปทับ = ถอด live wallpaper ออกจากจอล็อกเอง
- ยืด debounce ของการเปลี่ยนรูปจาก 2.5 เป็น 5 วินาที เดิมการสลับ visibility ตอนปลดล็อกทำให้เปลี่ยนรูปรัวสองครั้งใน 3 วินาที

**1.0.4** — ลองใช้ `setFixedSize` ขอ surface ใหม่ ระบบปฏิเสธ (เก็บไว้เป็นบันทึกว่าทางนี้ปิด)

**1.0.3** — เพิ่มหน้าบันทึกการทำงานในแอพ และตรวจจับว่า surface ติดโหมด canvas

**1.0.2** — วิดีโอไม่เล่น แก้ 4 จุดใน Live Wallpaper engine

- ใช้ `setVideoSurface(surface)` แทน `setVideoSurfaceHolder(holder)` ตัวหลังรอ callback `surfaceCreated` ซึ่งไม่มีวันมาถึง เพราะ wallpaper engine สร้าง surface เสร็จก่อนที่เราจะลงทะเบียน callback ได้ ผลคือวิดีโอเล่นอยู่แต่ไม่ได้วาดลงที่ไหนเลย
- `onSurfaceDestroyed` ล้าง `shownId` แล้ว เดิมค่าเก่าค้างอยู่ พอ surface ถูกสร้างใหม่ `render()` เข้าใจว่ารูปเดิมยังอยู่บนจอจึงไม่ต่อ player กลับเข้าไป
- เงื่อนไขข้ามการวาดใน `render()` ตรวจด้วยว่าเนื้อหาต่ออยู่จริงไหม ไม่ใช่ดูแค่ว่า id ตรงกัน
- โหมดปลดล็อก (ค่าเริ่มต้น) เรียก `render()` ทุกครั้งที่จอกลับมามองเห็น เดิมเรียกแต่ `advance()` ซึ่งมี debounce 2.5 วินาทีและทำงานคนละเธรด ถ้าโดน debounce ก็ไม่มีอะไรวาดเลย
- เพิ่ม `Player.Listener` log รหัสข้อผิดพลาดลง logcat และถ้าถอดรหัสวิดีโอไม่ได้ จะใช้เฟรมนิ่งแทนจอดำ

**1.0.1**

- แยกปุ่มเพิ่ม **รูป** กับ **วิดีโอ** ออกจากกัน ตัวเลือกไฟล์ของ One UI กรองไม่แม่นเมื่อส่ง `*/*` พร้อม `EXTRA_MIME_TYPES` หลายชนิด แล้วซ่อนวิดีโอทิ้ง การส่ง MIME ชนิดเดียวตรงๆ แก้ได้
- ข้อความแจ้งผลตอนเพิ่มไฟล์บอกแยกแล้วว่า เพิ่มได้กี่ไฟล์ ซ้ำกี่ไฟล์ ชนิดไม่รองรับกี่ไฟล์ อ่านไม่ได้กี่ไฟล์ เดิมขึ้นว่า "อยู่ในคลังแล้ว" ทุกกรณีที่เพิ่มไม่สำเร็จ
- โหมดแยกจอทำงานจริงแล้ว เดิมปิดสวิตช์ซิงก์แล้วสองจอยังขึ้นรูปเดียวกัน เพราะรูปทุกใบถูกแท็กทั้งสองจอเป็นค่าเริ่มต้น และตัวนับคิวทั้งสองเดินพร้อมกัน ตอนนี้แอพเลื่อนคิวจอล็อกให้พ้นรูปของหน้าจอหลักอัตโนมัติ การแตะรูปก็เคารพแท็ก H/L ของรูปนั้น และหน้าตั้งค่าแสดงจำนวนที่แท็กไว้พร้อมเตือนถ้ายังไม่มีรูปสำหรับจอล็อก

**1.0.0** เวอร์ชันแรก

## Build

มีสองทาง เลือกทางใดทางหนึ่ง

### ทาง A — GitHub Actions (ไม่ต้องลงอะไรในเครื่อง)

1. สร้างคีย์เซ็นชื่อ: `.\tools\create-keystore.ps1`
2. push โปรเจกต์ขึ้น GitHub repo แบบ private
3. ใส่ secret 4 ตัวตามไฟล์ `keystore\github-secrets.txt`
4. ไปแท็บ Actions กด **Build WallFlow** → **Run workflow**
5. ดาวน์โหลด artifact `wallflow-aab` เอาไปอัปโหลด Play Console

### ทาง B — เครื่องตัวเอง

```powershell
.\tools\setup-build-toolchain.ps1
& "$env:LOCALAPPDATA\Gradle\gradle-8.14.2\bin\gradle.bat" assembleDebug
```

หรือเปิดโฟลเดอร์นี้ด้วย Android Studio แล้วกด Run ตามปกติ

## ข้อจำกัดที่ต้องรู้ไว้

**วิดีโอบนจอล็อก ทำได้จริง** ทดสอบแล้วบน Galaxy S25+ (SM-S936B) Android 17 / One UI: ตอนกด "ตั้งค่าวอลเปเปอร์" ระบบให้เลือกสามแบบ และมี **"หน้าจอหลักและหน้าจอล็อก"** ให้ด้วย เมื่อเลือกอันนี้ engine ของเราคุมทั้งสองจอ วิดีโอจึงเล่นบนจอล็อกด้วย ยืนยันจาก `dumpsys wallpaper` ว่าทั้ง `mLastWallpaper` และ `mLastLockWallpaper` ชี้มาที่ `WallFlowWallpaperService`

สวิตช์ "มิเรอร์ไปจอล็อก" มีไว้สำหรับเครื่องที่ให้ลงได้แค่หน้าจอหลักเท่านั้น และแอพจะข้ามการมิเรอร์เองอัตโนมัติเมื่อตรวจพบว่า engine อยู่บนจอล็อกอยู่แล้ว

**ความละเอียดที่ระบบเก็บ** ต่อให้ป้อนไฟล์ 4K ระบบ Android จะย่อภาพลงเท่าขนาดจอก่อนเก็บเสมอ บนจอ 1440×3120 ของ S25+ จึงคมเท่ากัน ส่วนที่ได้ประโยชน์จากไฟล์ 4K จริงๆ คือตอนเปิด Ken Burns ซึ่งซูมเข้าไปในภาพ

**โหมดตามเวลา** ใช้ alarm แบบไม่เป๊ะเพื่อให้ระบบจัดคิวประหยัดแบตได้ เวลาอาจคลาดเคลื่อนไม่กี่นาทีตอนเครื่องหลับลึก ซึ่งแลกมากับการไม่ต้องขอสิทธิ์ exact alarm ที่ Play สงวนไว้ให้แอพนาฬิกาปลุก
